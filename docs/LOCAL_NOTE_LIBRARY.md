# 本地笔记库与图片收藏方案

状态：v0.6.0 已实现首版。自动化测试覆盖本地文件写入、图片采集、按需阅读、迁移和恢复。真实 ChatGPT 图片下载与 Chrome 授权生命周期仍需浏览器实测。

实现差异：文件名采用对话与消息标识的 SHA-256 值，标题保存在 Markdown 属性和索引中；图片采用笔记内顺序编号。下载当前页面展示的图片版本，不保证原始分辨率。暂不支持的图片来源会被跳过并保留正文；网络或读取失败时整条收藏不提交，可点击收藏重试。正文保存在 Markdown 中，不另存完整 HTML 快照。删除采用从列表隐藏，磁盘文件保留。

## v0.5.0 行为（改造前）

- `src/content/messages.ts` 在快照中移除 `img`，且拒绝没有文字的回复。
- `src/export/obsidian.ts` 在 Markdown 转换中再次移除图片。
- `ChromeStorageRepository` 将全部正文和 HTML 写入 `chrome.storage.local`。
- 当前目录选择仅用于手动导出，不改变收藏的主存储位置。

## 产品决策

首次使用必须选择本地笔记库并获得写入授权，随后才能收藏。使用系统文件夹选择器，而不是只能填写字符串的路径输入框：目录句柄才是现有实现取得文件访问能力的入口。可选择普通文件夹，也可选择 Obsidian 仓库；Obsidian 不作为必需依赖。

笔记库下有多个笔记本，默认“收件箱”。侧栏显示当前笔记本，页面收藏按钮默认保存至该笔记本。保存后可在侧栏移动。第一版不做自动内容分类。

图片是笔记的附件，不单独建立“附件笔记本”。纯图片收藏也创建 Markdown 笔记，保留标题、来源、时间和图片引用。后续图片视图从附件索引生成，不复制图片。

```text
我的笔记库/
  .guiderail/
    library.json
    index.json
  收件箱/
    回复标题--稳定ID.md
    attachments/
      稳定ID/
        图片内容哈希.png
  设计参考/
    图片标题--稳定ID.md
    attachments/
      稳定ID/
        图片内容哈希.webp
```

附件按笔记分组，便于移动、清理与避免跨笔记误删。第一版只在单条笔记内去重；重复收藏通过对话 ID 与消息 ID 识别。文件名清理特殊字符并限制长度；笔记 ID 不随标题改变。Markdown 使用相对图片路径，保持普通编辑器与 Obsidian 可读。

## 首次设置与正常使用

1. 初始页面展示“选择笔记库文件夹”、用途说明和默认笔记本“收件箱”。支持在独立扩展标签页完成设置，目录选择失败时给出入口。
2. 检查目录授权、库格式和可写性；已有库直接打开，新库仅创建自有元数据和默认笔记本，避免覆盖其他文件。
3. 设置完成后展示当前库名称、笔记本、最近收藏。目录句柄不一定暴露绝对路径，界面不可伪造完整路径。
4. 点击收藏，抓取正文与图片，写入选中笔记本。只有文件提交成功后才显示“已保存到：笔记本”。
5. 未设置库时，页面按钮提示“请先在插件中设置笔记库”。失去权限时提示重新授权；目录不可用时暂停保存并支持重试。

浏览器重启后的句柄权限、侧栏目录选择以及侧栏关闭后的后台写入，必须在目标 Chrome 版本实测。后台不能依赖自动弹出授权对话框。目录访问失败时不静默回退为 Chrome 正文存储。

## 存储与写入一致性

- 本地文件保存正文、图片和可重建索引；Chrome 仅保存目录句柄、当前库/笔记本与少量设置，不持久化完整正文、图片或无限增长的失败队列。
- 读取列表采用索引，打开笔记时再读取文件。外部编辑的笔记不可被自动覆盖；索引损坏支持从文件重建。
- 单一写入队列协调多个页面；写入时固定目标库和笔记本，防止用户切换导致错位。
- 先保存附件，再提交引用这些附件的笔记，最后更新索引；文件系统多文件操作不是事务，需要记录操作状态并支持中断恢复。
- 下载失败显示“图片未保存”，不能报完整成功。可显式保存文字和失败占位，再重试附件；纯图片下载失败不报收藏成功。
- 索引更新失败时仍识别已写笔记，重试不得重复创建。清理仅针对确认属于未完成操作的文件。
- 删除收藏默认仅从列表移除；删除磁盘笔记需明确动作。附件清理只删除确认无引用且由插件管理的文件。
- 切换库不自动搬移旧文件；移动笔记本时一起移动笔记及其附件目录，更新相对引用，失败可恢复。

## 图片采集

第一版支持收藏整条回复中的全部图片，包括纯图片回复。后续再加单图收藏与图片筛选。

- 在消息内容范围内识别图片，排除头像、图标、按钮、加载占位和插件节点；保留图片与正文顺序。
- 优先获取可访问的原图；只能获取预览时标注“预览图”，不宣称原图。
- 网络图片、登录保护资源、临时地址、blob 图片分别验证获取路径；blob 内容需要在仍可访问该资源的页面上下文及时获取。
- 不依赖未公开且未经验证的 ChatGPT 下载接口，也不把临时远程 URL 当作已保存附件。
- 校验响应状态、实际图片格式、大小及超时；限制单图大小和并发，下载过程使用短期内存，不写入 Chrome 永久存储。
- 只添加验证所需的最小来源权限，不预先请求全部网站访问权限。
- 阅读器通过本地文件生成临时对象 URL 并及时释放，不使用远程图片作为离线收藏的替代。

## 旧收藏迁移

用户选择目录后，展示旧收藏条数并提供迁移。逐条写入、校验、记录进度；发生错误保留原数据并支持继续。全部验证成功后再提供“释放 Chrome 中的旧收藏内容”，清理前明确说明范围。旧任务规划数据单独保留或备份，不因迁移回复而直接清空。曾被过滤的图片不在旧数据里，需回到原对话重新收藏。

## 实施顺序与验收

1. 目录能力验证：首次授权、重启再授权、侧栏关闭后写入、后台中断恢复。
2. 文件库基础：设置入口、笔记本、Markdown 自动写入、按需读取、外部修改保护和旧数据迁移。
3. 图片链路：真实生成图片与纯图片回复、相对引用、本地阅读、失败重试与容量限制。
4. 整理功能：移动笔记、附件回收、库切换与索引重建。

核心验收：未设置目录不能收藏；保存后目标目录立即有文件；断网可读已保存图片；Chrome 存储不随正文和图片体积增长；拒绝权限、磁盘写入失败、下载失败不显示完整成功；重复收藏不覆盖用户修改；迁移中断不丢旧数据。
